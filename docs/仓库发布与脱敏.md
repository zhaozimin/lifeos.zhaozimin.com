# 仓库发布与脱敏

Git保存源码、配置模板、合成数据和脱敏文档。
生产运行状态和私人资料不作为源码分发。

## 保留内容

保留LifeOS名称、Logo、作者品牌及公开网站。
保留纸墨朱设计系统和产品推广链接。
保留技术栈名称、第三方服务名称和合成演示数据。
不为信息脱敏删除品牌或广告内容。

## 私有内容

凭据、令牌、TOTP密钥及二维码不得提交。
数据库、原话、财务、健康和账号资料不得提交。
源站地址、云账号和内部资源编号不得提交。
本机个人路径与完整运维日志不随源码上传。
真实消费、活动时段、健康统计和消息数量不得提交。
实例容量、主机规格、生产版本和备份对象名不得提交。
原始证据保持真实；移入私有归档后只分发验收结论。

生产配置放在Git忽略的本机文件中。
示例配置使用占位符，部署者填写自己的资源。
订阅内部服务使用wrangler.example.toml作为模板。
实际wrangler.toml不受Git跟踪，本机部署继续使用它。

完整原始运维文档位于.private/github-release/docs/。
修改前源码快照和Git bundle位于.private/github-backup/。
这些目录受.gitignore保护，不得强行加入Git。

## 发布前检查

检查git status与暂存差异。
确认没有凭据、数据库、私有归档和生产配置。
检查README语言切换、Logo和本地链接。
运行受影响的构建与测试。
扫描待提交文件和所有分发历史。
检查器同时检查未跟踪文件与暂存版本。
自然语言规则只辅助人工复核，不能覆盖全部隐私。

```sh
python3 ops/check-public-repo.py --history
python3 ops/check_public_repo_test.py
gitleaks git --redact=100 --log-opts=--all
```

检查器只输出规则名和路径，不打印敏感正文。

历史已含私人信息时，清理历史后再推送。
使用本机私有bundle保留可恢复的原始历史。
推送时检查远端原提交，防止覆盖新增工作。
不要把未脱敏的备份分支或标签上传GitHub。

若发现真实密钥曾上传，必须轮换密钥。
改写Git历史不能保证清除托管平台的缓存。
推送后从GitHub重新克隆，再扫描全部分支和标签。
逐一复核已知旧提交的提交、文件与归档入口。
旧对象仍可读取时，保持仓库私有并跟进平台清除。
GitHub平台方负责清除托管旧对象与缓存。
按[官方流程](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)提交请求并保存核验结果。
