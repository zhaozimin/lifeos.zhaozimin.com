# 功能缺口与采集路线

核对日期：北京时间2026-10-26。
本页回答增加哪些功能，不重复列运行验收任务。
功能已实现不表示持续使用验收已经通过。

## 核对依据

行动方案.html定义开发阶段与当前产品边界。
量化自我方案.html的完整采集清单共有26项。
采集清单的P0/P1/P2表示优先级。
它们与行动方案的P0至P5开发阶段不同。

本机没有找到独立的《赛博人生》采集文件。
已检查Obsidian中的“赛博永生”库。
其知识索引仍为空，LifeOS尚未接入该知识库。
本页不把同名无关网页当成本人的计划。

原话归档、结构化记录和分析功能分别核对。
MemOS保存微信语义记忆，不代替领域账表。
账户和项目复用local_records，不以缺少同名表判未实现。
健康每日感受已存在，不重复建设同一种入口。

| 跨领域分析 | WHOOP已有健康域趋势、配对与训练建议 | 结合工作、睡眠、精力、消费和目标的数据分析 |

结构化体检、保单和合同也共用文档提取流程。
原件保存和字段确认属于新模块。
既有财务附件入口不等于已具备这些提取能力。
保单还缺保额、续费日和到期提醒。
合同还缺金额、关键日期与对应事项。

## 建议的功能批次

### 第一批：补完原计划的日常核心

1. 微信精力与心情评分，复用健康页已有精力定义。
2. 微信晚间三问复盘，保存可查询的回答。
3. 通用目标与可确认的个人画像。
4. 微信按日期查询真实时间账、流水和睡眠。

每个新领域统一接入既有微信收件与回执。
每句话先保留原话，再按领域保存字段。
纯问答不新增业务记录。
微信例句如“精力3分，心情4分”仅代表计划交互。
这些新指令尚未实现，不能当成当前可用说明。

### 第二批：增加自动来源并形成报告

1. 日历、电脑和App时长。
2. 体重体脂与饮食结构化记录。
3. 资产快照、订阅与流水的关联、月度对账。
4. 体检文档与确认后指标趋势。
5. 有数据来源引用的综合晨报、周报和月报。

体检与资产虽在第二批实施建议中，原清单仍是P0。
此排期按日常记录频率与依赖排序，不改原优先级。
晚间复盘时间22:30与现有小结23:30需统一偏好。
避免同一晚上发两条重复的账本汇总。

### 第三批：成长与知识

1. 人脉、交流和承诺追踪。
2. 阅读课程、产出和决策复查。
3. Obsidian所选笔记的只读接入。
4. 个人实验及跨领域分析。
5. 对话专页和其他AI客户端记忆接入。

“赛博永生”库保留用户触发提炼的既有规则。
不得因LifeOS接入而暗中添加后台提炼任务。
其原料层保持只读，知识编译另作明确动作。

### 第四批：补充来源

录音转写、邮件、手机健康、位置、天气和年度回顾。
录音来源可先支持导出的文字，再扩展实时输入。
具体设备和接入供应商另按用户实际选择确定。
