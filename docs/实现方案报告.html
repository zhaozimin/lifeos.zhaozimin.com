24 小时随身管家：可以做，但要换掉一个零件

目标：手机随时说一句话，管家记下时间、开销、身体和生活。数据进 Supabase，长期记忆进 MemOS，你在自己的网站上用三重验证登录看面板。

结论
  1. 整体方案可以实现。所有零件都有现成的开源项目或官方 API，不需要从零造轮子。
  2. 旧结论作废。独立的 Antigravity CLI 官方支持无界面调用。CLI 已安装，Gemini 3.8 调用已验收；微信后端的正式解析接入方式待确认。
  3. 区分产品形态。桌面 IDE 留在本机；官方独立 CLI 以 VPS 的 lifeos 专用用户运行。
  4. Supabase 免费版不做自动备份，项目 7 天没人访问会被暂停。"安全保留"必须靠 VPS 每晚自己导出加密备份。
  5. "24 小时录音"是最难的一环。手机无法稳定地全天后台录音（尤其是 iPhone），要配一个录音挂件。推荐 Omi，因为它有实时转写 Webhook。

1. 你没问但必须知道的事

下面这些点，不在早期定下来，后面会导致返工。

① 更正：独立 CLI 与桌面 IDE 必须分开判断。 独立 Antigravity CLI 已提供官方 Linux 安装器、SSH OAuth 和无界面 JSON 输出。个人订阅不支持将 CLI 封装进第三方应用，业务接入须单独确认授权。旧稿关于缺少官方无界面模式的判断作废，后文保留历史推演。
② "Memos" 有两个，别装错。 你给的链接是 MemTensor/MemOS，它是给 AI 用的"记忆操作系统"，存的是语义记忆，供 Agent 检索。另一个同名项目 usememos/memos 是给人写的笔记 App。本方案用的是前者。注意：MemOS 自建版要同时跑 Neo4j 和 Qdrant 两个数据库，内存最好在 4GB 以上。VPS 太小的话，先用 MemOS 云服务，或者先用 Supabase 自带的 pgvector 代替。
③ 唯一真源（Single Source of Truth）。 你会有本机 LifeOS、VPS 管家、Supabase、MemOS 四个地方存数据。必须规定：Supabase 是唯一真源。MemOS 只放从 Supabase 提炼出来的记忆，丢了可以重建。本机 LifeOS 通过 Supabase MCP 读写，不再自己保存一份账本。不这样定，三个月后你会看到两个对不上的账本。
④ 免费 Supabase 的三个坑。 (a) 数据库只有 500MB。(b) 没有自动备份。(c) 7 天不活跃会被暂停。
对策：只存文字，不存音频（一天录音约 150MB，三天就满）。VPS 每天定时拉数据，项目自然保持活跃。每晚 pg_dump 一次，加密后存到 Cloudflare R2 或你的 Mac。另外，Supabase 从 2026-10-30 起要求免费项目给 PostgREST 显式授权，建表时就写好 GRANT 语句。
⑤ 录音的法律和隐私。 全天录音一定会录到别人的声音。自己存档、自己看，一般问题不大。但不要公开或外传，在会议、医院等场合要主动关掉。技术上建议：转写完成后删除原始音频，只保留文字和摘要。这样既省空间，泄露时伤害也小。
⑥ "二级密钥"有更好的做法。 自己发明一个"第二密码"，安全性其实不如行业标准。推荐的三重验证：密码 + TOTP 动态码 + Passkey（Face ID / 指纹）。外面再加一层 Cloudflare Access 拦截陌生访问。这样别人连登录页都看不到。详见第 5 节。
⑦ 记账和时间统计的关键不是 AI，是分类表。 柳比歇夫法真正的价值，在于长期使用同一套分类：第一类工作、第二类工作、休息、通勤等等。AI 只负责把"刚吃了个午饭 38 块，花了 40 分钟"拆成两条结构化记录。分类表要先由你定好，再写进 Hermes 的 skill 里。分类一旦变来变去，年度统计就没有意义了。

2. 总体架构

分四层：采集层（手机、挂件、Whoop）→ 处理层（VPS 上的 Hermes）→ 存储层（Supabase + MemOS）→ 展示层（你的网站）。

3. 四条数据管线

难度低A. 时间统计（柳比歇夫）
  • 你对 Telegram 说："刚写完方案，1 小时 20 分。"
  • Hermes 用 skill 解析出：开始时间、结束时间、分类、事项。
  • 写入 time_entries 表，回一句确认，可以撤销。
  • 每晚自动检查时间空洞，例如"14:00–16:30 没有记录，你在做什么？"
难度低B. 记账
  • "午饭 38，微信付的。"→ 金额、币种、分类、账户、时间。
  • 写入 transactions 表。金额用整数"分"存储，不用浮点数。
  • 一句话里同时有时间和金额时，同时生成两条记录，并互相关联。
  • 以后可以加：截图识别支付通知、导入月度账单做对账。
难度中C. Whoop 身体数据
  • 在 developer.whoop.com 注册应用，走 OAuth 2.0 授权一次。refresh token 存在 VPS 上。
  • 恢复、睡眠、训练用 Webhook 实时推送（HMAC 签名，必须验签）。
  • 每日 Strain、周期、身体测量没有 Webhook，每小时轮询一次。
  • 用 v2 API。v1 Webhook 已经停用。
难度高D. 24 小时录音 → 文字 → 摘要
  • 推荐 Omi 挂件：开源，提供实时转写 Webhook，按片段推送到你的 Ingest API。
  • Plaud 类录音笔音质好，但没有稳定的公开 API，只能半自动导出。
  • 只用手机：Android 可以，耗电大；iPhone 后台会被系统杀掉，不可行。
  • 每晚 Hermes 把当天的转写分段、打标签、生成摘要，写入 daily_digest，再提炼成记忆送进 MemOS。
  • 摘要还能反向补全时间统计。例如"14:00–15:10 在和某人谈合作"。

4. 数据库设计（初稿）

原则：原始输入和结构化结果分开存。AI 解析错了，可以从原话重新解析，不会丢信息。

raw_inputs      -- 每条原话 / 语音转写：source, text, received_at, parsed(bool)
time_entries    -- 柳比歇夫：start_at, end_at, category_id, activity, raw_input_id
categories      -- 你定义的分类树（第一类工作 / 第二类 / 休息…），很少变动
transactions    -- 账目：amount_cents, currency, category, account, occurred_at, raw_input_id
whoop_recovery  -- recovery_score, hrv, rhr, spo2, skin_temp, sleep_id(uuid)
whoop_sleep     -- stages, efficiency, performance, respiratory_rate
whoop_workout   -- strain, sport, hr_zones
whoop_cycle     -- 每日 strain（轮询获得）
transcripts     -- 录音片段：start_at, end_at, speaker, text（不存音频）
daily_digest    -- 每日摘要：date, summary, highlights, mood, auto_time_blocks(jsonb)

所有表都开启 RLS，只允许你本人的 user_id 读写。VPS 写入用 service_role key，这个 key 只放在 VPS 的环境变量里，绝不进前端。

5. 三重登录安全

你的要求是"别人知道网址也登不上去"。下面的设计能做到"别人知道网址也看不到登录框"。

层机制防的是什么
0 · 门禁Cloudflare Access：只放行你的邮箱验证码或 GitHub 账号扫描器、撞库机器人。他们连页面都看不到。
1 · 你知道的Supabase Auth 密码（长密码，存在密码管理器里）只拿到你设备的人
2 · 你拥有的TOTP 动态码（Supabase 原生 MFA，可以用 1Password 或 Google Authenticator）密码泄露
3 · 你本人Passkey / WebAuthn（Face ID、指纹）——代替你说的"二级密钥"钓鱼网站。Passkey 绑定域名，假网站拿不到。

补充措施：会话 7 天过期；新设备登录时 Telegram 推送提醒；准备一组离线恢复码，打印出来放在家里。

注意Telegram Bot 本身也是入口。在代码里只允许你的 Telegram user_id 和 bot 对话，其他人发来的消息一律忽略。

7. 分阶段路线图

每个阶段结束时都能独立使用，不搞一次性大爆炸上线。

阶段 1约 1 周
管家能记账、记时间。VPS 装 Hermes 并用 systemd 托管 → 建 Supabase 表和 RLS → 写柳比歇夫和记账 skill → 接 Telegram → 每晚备份。
验收：连续 7 天只用 Telegram 记录，数据不丢、分类正确。
阶段 2约 1 周
网站和门禁上线。Next.js 面板（今日、时间、金钱三页）→ Cloudflare Access → 密码 + TOTP + Passkey。
验收：手机能登录看面板；无痕窗口访问时被 Cloudflare 拦下。
阶段 33–5 天
接入 Whoop。OAuth 授权、Webhook 验签、轮询补齐、身体页面。
阶段 41–2 周
24 小时录音。购买 Omi → Ingest API 接 Webhook → 每晚生成摘要 → 自动补全时间空洞。
阶段 5按需
长期记忆。先用 pgvector 做检索；VPS 扩容后再部署 MemOS，把每日摘要提炼成长期记忆。本机 LifeOS 改为通过 MCP 读取。

9. 风险清单

风险级别对策
Supabase 免费版无备份，误删或被暂停高每晚 pg_dump，加密后异地存储；每月演练一次恢复
service_role key 或 Whoop token 泄露高只放 VPS 环境变量；VPS 只开 SSH 密钥登录 + 防火墙
录音涉及他人隐私中转写后删除音频；不外传；敏感场合关闭
AI 解析错账中保留原话；每条记录回执确认；支持一键撤销
分类表频繁变动，统计失效中分类只增不改，旧分类做映射
第三方 API 变更（Whoop / Omi）低适配器隔离：每个数据源一个模块，坏一个不影响其他
