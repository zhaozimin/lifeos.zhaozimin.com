# 健康接入

唯一入口：`/dashboard/health`（跳到 `/dashboard/health/overview`），一级栏显示“健康”；六个视图各有路由 `/dashboard/health/:view`，二级栏底部「周 月 季」切换最近 7/30/90 天。
身体总览、趋势、每日建议、训练、感受和设置在页内切换。
复用原版图表，保留悬停、键盘、触屏和详情。
原版样式在同源框架中隔离，继承主站主题。
所有健康API要求本人密码加TOTP。

## 迁移与数据位置

WHOOP官方v2 → VPS私有SQLite → Supabase发布副本 → 健康页。
WHOOP为源，SQLite为工作库，Supabase为发布副本。
迁移本机v0.4.0的记录、偏好、授权和报告修订。
VPS应用为`/opt/lifeos-whoop`，服务为`lifeos-whoop.service`。
工作库为`/var/lib/lifeos-whoop/lifeos.sqlite`。
独立Linux用户，仅监听`127.0.0.1:3210`。
本机原同步进程停用，避免刷新令牌互相作废。
旧localhost入口通过SSH隧道用于维护。

| 数据 | 云端位置 |
|---|---|
| 周期、恢复、睡眠、训练原始记录 | whoop_records |
| 图表、状态、感受和导出摘要 | whoop_publications |
| 各日期报告与修订 | whoop_plans |
| 同步、重算、偏好和感受操作 | whoop_jobs |
| 晨间微信回执 | raw_inputs，source=system |

页面只读副本，写入先进入本人AAL2白名单队列。
操作超时后先核查任务，不重发同一写入。
OAuth凭据变更不在云端队列白名单内。
令牌不进入发布表、浏览器或模型。
公开静态资源没有身体数据，API仍需双重登录。

## 时间轴校准

发布WHOOP副本后执行reconcile_whoop_time。
夜间和午睡的SCORED实睡覆盖手工估计。
首尾手机时间按本人规则推定并归娱乐。
会话内部清醒只扣减，不推定为手机。
原始行软删除，原话、边界和审计版本保留。
重算、待确认与日期口径见时间分类与睡眠规则.md。

## 晨间计划

沿用Asia/Shanghai，07:00发布，06:00准备。
训练目标、经验与身体限制由部署者设置。
偏好和报告日程可修改，账本时区不随之改变。
每次发布先同步，再读取当天主睡眠和恢复。
只使用SCORED且非校准中的恢复数据。
基线取目标日期之前28天，不足14次不判断高低。
未评分或同步失败时等待，每5分钟重试。
等待时不发布训练剂量，不沿用昨日分数加量。
计划说明活动、时长、调整方式和数据依据。
身体不适和医嘱优先于手环分数。
恢复规则复用原项目，不把指标交给模型猜测。

设置时间到12:00之间，复用微信既有回执队列。
每天最多一条，修订和重复调度不重复发送。
需要24小时内的有效微信会话。
缺会话时保留网页计划，窗口内继续尝试。
迁移当晚不补发早晨旧计划，23:30小结开关不变。

## 边界与验收

沿用30分钟轮询，首批不启用Webhook。
原版尚不自动镜像WHOOP历史删除。
感受和身体限制为空，不代表已确认没有限制。
本轮不采集或迁移Obsidian笔记。
云端身体副本和报告进入加密R2备份。
普通副本不含OAuth令牌，VPS丢失后需重新授权。

迁移核对记录数量、主键、载荷和报告修订。
验证真实图表、设置和异步操作完成。
验证未登录、AAL1和异主不能读取。
验证晨间队列去重、评分门槛和时间窗。
连续3天同步和实际晨间收件需跨日观察。
