子民的量化自我

量化自我（Quantified Self）的核心不是"收集一切"，而是"先有问题，再收集刚好够回答问题的数据"。本文定义要采集哪些数据、用什么工具、怎么处理，以及 AI 怎么用这些数据给你定制方案。施工细节见同目录的 行动方案.html：本文回答"做什么、为什么"，行动方案回答"怎么搭"。

拿不到的数据怎么办

原则：不求全量，只求信号。你需要的不是全部聊天记录，而是聊天记录里的三样东西：见了谁、聊了什么事、答应了什么。用成本低的"代理数据"拿到这三样，效果和全量记录差不多，风险小得多。
数据能不能拿到建议做法
邮件能大部分邮箱支持 IMAP 只读访问不存全文。每小时读取新邮件，只存发件人、主题、时间，再由 AI 提取摘要和待办。工作邮箱先确认公司政策是否允许
微信聊天不建议没有官方接口第三方解密本地数据库的工具违反微信条款，版本一升级就失效，而且涉及大量他人隐私。改用三个代理：① 晚间复盘时说一句"今天和谁谈了什么"；② 重要的结论截图，或者直接复述给机器人；③ 以后用录音覆盖线下对话
短信、电话部分Android 可以导出，iPhone 很难价值低，跳过
社交媒体部分大部分平台支持申请数据导出只关心自己的发布内容时，每年导出一次存档即可
浏览记录能ActivityWatch 浏览器插件只统计网站时长，不存具体网址

体检报告等文档

应该上传。体检报告是价值最高的数据之一：一年一份，但能看出身体多年的趋势。关键是把照片变成一个个指标，而不只是存一张图片。

处理流程

  1. 上传：在网站的上传页面提交照片或 PDF。不走微信，因为微信机器人通道收文件不稳定。
  2. 存原件：原文件存进 Supabase Storage 的私有目录。原件永远保留，作为依据。
  3. AI 提取：解析器（agy + Gemini）读取图片或 PDF，输出每个指标：名称、数值、单位、参考范围、是否异常、检查日期、机构。
  4. 人工确认（必须做）：网站把原图和提取结果并排显示，你逐项确认或修改。医疗数字识别错一位就会误导判断，不确认的结果不入库。
  5. 入库：写入 lab_results 表。同一个指标统一名称和单位，例如"低密度脂蛋白"统一记为 LDL-C，单位 mmol/L。
  6. 出趋势：网站为每个指标画多年趋势线。AI 只提示"这项指标连续两年上升，建议咨询医生"，不做诊断。

数据处理标准流程

不管哪一类数据，都走同一条流水线。新增一类数据，只需要写一个新的"采集器"，后面的步骤全部复用。

每条数据都必须带的五个字段

字段含义为什么
source来自哪里：wechat、whoop、upload、imap……出错时能追到源头
occurred_at事情发生的时间（带时区）和"记录时间"区分开。补记昨天的事很常见
raw_ref指向原始记录的 ID结构化结果错了，可以从原始记录重新生成
confidence可信度：confirmed（人工确认）、parsed（AI 提取）、estimated（估算）AI 分析时区别对待。估算的饮食热量不能当准确值用
deleted_at软删除标记撤销操作可以恢复，历史可追溯

另外三条规则：缺失不等于零（没记录就是 null，图表不能画成 0）；单位统一（金额用分，体重用 kg，时间用 timestamptz）；分类只增不改。本人明确要求重分类时，保留原始时段与版本后应用新大类。2026-10-26起夜间和午睡均以WHOOP已评分实睡校准；手工睡眠首尾差额按本人规则推定刷手机。具体口径见时间分类与睡眠规则.md。

AI 怎么用这些数据

两种方式：你问它答（随时），它定时给你（固定节奏）。两种方式都遵循同一个做法：程序先用 SQL 算好一份数据快照，再连同画像一起交给 AI。AI 不直接读数据库。

固定节奏

时间内容用到的数据送达
每天 07:00今日建议：适合高强度工作还是恢复；今天日程里最重要的一件事Whoop 恢复、睡眠、日历、目标微信一条
每天 22:30复盘提问 + 今日小结：时间分布、支出、没记录的时间段时间、金钱、精力微信一条
每周日周报：时间去哪了、钱去哪了、精力的规律、离目标还差多少、下周三条建议全部网站全文 + 微信摘要
每月 1 日月报：净资产变化、身体趋势、目标进度、实验结论全部网站
每年末年度回顾：一年的时间账、身体变化、体检对比、关键决策复查全部网站

你可以随时问的问题（示例）

  • "上个月我的深度工作时间为什么少了？"
  • "我睡够 7 小时的第二天，工作效率是不是更高？"
  • "哪些消费发生在我精力低的日子？"
  • "我多久没联系老王了？上次我答应他什么？"
  • "按现在的节奏，年底能完成目标吗？"
  • "我的血脂这几年是什么趋势？"

保证 AI 说得对的四条规则

  1. 数字由 SQL 算，AI 只解读。回答里出现的每个数字都必须来自快照。
  2. 相关不等于因果。AI 发现"喝咖啡的日子效率高"时，必须说成"相关"，并建议用个人实验来验证。
  3. 样本太少时不下结论。少于 14 个数据点，只描述情况，不判断规律。本机 Whoop 项目已经在用这条规则。
  4. 不做医疗诊断。健康相关的内容只描述趋势，建议咨询医生。

个人实验

个人实验是量化自我区别于普通记录的关键：不只是观察自己，还要主动改变一件事，看数据怎么变。这在研究里叫 N-of-1 实验，即样本只有你一个人的实验。

步骤示例
假设晚上 22:00 后不看手机，我的睡眠会变好
指标Whoop 睡眠表现分、入睡时间、第二天早上的精力分
基线实验前 14 天的数据（系统里已经有了）
干预连续 14 天执行，每天在微信里说"实验打卡"
结论系统自动对比前后 14 天，AI 写一段结论，存入 insights

每个季度做 1–2 个实验就够。AI 也可以根据你的数据提出实验建议。

隐私分级

数据越敏感，交给 AI 的内容越少，存储越严格。

级别数据交给 AI 的方式存储
L1 普通时间记录、读书、灵感、天气明细可以发送常规
L2 个人精力、情绪、复盘、日程、屏幕时间明细可以发送，去掉他人姓名常规
L3 敏感财务、资产、位置、人际、邮件摘要只发汇总值（按分类合计、按月），不发账号和具体地址账号只存后四位
L4 高敏医疗、体检、他人的对话、声纹只发你选中的指标趋势；他人的原话不发原件存在私有目录；每年检查一次谁能访问

另外：你的数据会经过 Google（Gemini）。请查看 Gemini 订阅条款里关于数据用途的规定，确认后再决定 L3、L4 数据的发送范围。

落地节奏

不要一次全部上线。每个阶段先用满一个月，确认坚持得下来，再加下一批。

绿点是进入下一批的条件。一批没有坚持下来，就先简化这一批，不急着加新的。

五个常见误区

1. 收集癖

什么都记，但从来不看。对策：每类数据都要写明回答哪个问题；连续三个月没被任何报告用到的数据，停止采集。

2. 记录疲劳

手动记录太多，两周后放弃。对策：主动记录每天不超过 5 分钟；能自动采集的，绝不手动。

3. 被指标绑架

为了让数字好看而改变行为，比如为了恢复分不敢训练。对策：指标服务目标，每季度检查一次指标是否还和目标一致。

4. 完美主义

漏记一天就觉得数据没用了。对策：缺失就是缺失，系统允许空白。连续 80% 的覆盖率已经足够看出规律。

5. 相信 AI 编的数字

AI 自己算数，或者把相关说成因果。对策：数字全部由 SQL 计算，因果结论必须经过个人实验验证。

两个数据库的关系

Whoop 云端是原始真源，随时可以重新拉取。VPS 上的 SQLite 是这个控制台自己的工作库。Supabase 是发布出来的副本，供网站和 AI 使用。这三者的关系写进项目的 L1 文档，避免以后有人搞混。

迁移步骤

  1. 在项目里增加 Supabase 出口模块，并补测试。
  2. 增加独立systemd服务，沿用现有运行与备份方式。
  3. 本机执行 npm run service:uninstall，停止后台服务。
  4. 把 .data/lifeos.sqlite 和 .env 复制到 VPS 的数据卷（里面有令牌和历史数据，不需要重新授权）。
  5. 启动 VPS 服务，一次性把历史记录全部推送到 Supabase。
  6. 验收：连续 3 天，晨间报告按时在 07:00 发布，新数据 30 分钟内出现在 Supabase。

统一健康页采用原版图表和交互，通过本人AAL2读取副本。当天数据未评分或同步失败时等待；晨间微信投递在设置时间至12:00间每天最多一次，并要求24小时内的会话。Webhook和历史删除镜像尚未开启。
